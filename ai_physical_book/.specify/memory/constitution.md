# Physical AI & Humanoid Robotics — An Agentic, Spec-Kit Native Textbook Constitution

## Core Principles

### I. Spec-Kit Native Development
The textbook itself MUST adhere to the Spec-Kit pattern for development, ensuring a structured approach to content creation.
*Rationale:* This aligns with the "Agentic, Spec-Kit Native Textbook" title and ensures the book's development mirrors the principles it teaches.

### II. Comprehensive Content
The textbook MUST cover all specified chapters (Introduction to Physical AI, ROS 2, Digital Twin Simulation, NVIDIA Isaac, Vision-Language-Action, Humanoid Robotics Development, Building the AI-Native Textbook, Personalization, Translation & Subagents, Capstone Project) and required elements (clear explanations, architecture diagrams (ASCII), code samples, Docusaurus-ready MDX format, RAG chatbot integration instructions, MCP Context7 server usage, clarification prompts, Urdu translation prompts, personalization prompts, Subagents & Skills definitions).
*Rationale:* To deliver a complete and valuable resource as outlined by the user's initial request.

### III. Docusaurus-Ready MDX Format
All content MUST be produced in MDX format, compatible with Docusaurus for seamless publication.
*Rationale:* To facilitate the building of the AI-Native Textbook using Docusaurus as specified in Chapter 7.

### IV. Practical & Actionable Code Samples
Code samples MUST be relevant, practical, and include examples for ROS2, rclpy, Gazebo, and Isaac, demonstrating key concepts.
*Rationale:* To provide hands-on learning and demonstrate concepts effectively, as required by the user.

### V. AI-Native Features Integration
The textbook MUST include RAG chatbot integration instructions, MCP Context7 server usage instructions, clarification prompts, Urdu translation prompts, and personalization prompts. It MUST also include definitions for Claude Code Subagents and reusable Agent Skills.
*Rationale:* To showcase and enable the "AI-Native" aspect of the textbook and provide advanced features and extensibility.

### VI. Authoritative and Technical Voice
The voice MUST be authoritative, clear, technical, and fully aligned with Spec-Kit culture throughout the entire textbook.
*Rationale:* To establish credibility and ensure consistency in tone throughout the textbook, reflecting expert knowledge.

## Governance

This Constitution outlines the foundational principles and guidelines for the development of the "Physical AI & Humanoid Robotics — An Agentic, Spec-Kit Native Textbook." It supersedes all other conflicting practices and internal agreements.

**Amendment Procedure:** Any amendments to this Constitution require documentation of changes, explicit approval from project stakeholders, and a clear migration plan for affected artifacts.

**Versioning Policy:** The Constitution version adheres to semantic versioning (MAJOR.MINOR.PATCH).
- **MAJOR:** Backward incompatible governance/principle removals or redefinitions.
- **MINOR:** New principle/section added or materially expanded guidance.
- **PATCH:** Clarifications, wording, typo fixes, non-semantic refinements.

**Compliance Review:** All development activities, including PRs and code reviews, MUST verify compliance with the principles and rules outlined herein. Any introduced complexity MUST be justified against these principles.
